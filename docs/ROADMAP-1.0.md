# I.S.A.A.C. — Roadmap to 1.0 ("SOTA, for real")

> Status: drafted at **0.4.0** (2026-06-02). This is the complete plan to take
> I.S.A.A.C. from a strong, green-CI *framework* to a release we can honestly
> call a 1.0 general assistant — and, only with evidence in hand, "SOTA".

---

## 0. Honest starting point (what 0.4.0 actually is)

**Strong:** a coherent, broad architecture — `AgentLoop`, a 9-member specialist
team + `Orchestrator`, 5-layer memory, self-improvement engine, constitutional
safety, local-first LLM stack, MCP server, multimodal, ARC solver. 461 tests
pass; lint + tests green on Python 3.10/3.11/3.12.

**Not yet proven:** every test mocks the LLM, so nothing is validated
end-to-end against a live model; there are **no benchmark numbers**; the new
host-reach tools (`shell`, `fs_*`) are a real liability surface; and the
default local engine (a 7B model) caps real-world capability well below a
frontier-model assistant.

**Therefore:** "SOTA" and "1.0" are *claims that require evidence and
hardening*, not adjectives we can attach today. This document is how we earn them.

---

## 1. Definition of Done for 1.0 (the exit checklist)

1.0 ships only when **all** of these are true:

- [ ] **Benchmark evidence**: a reproducible score on at least one public agent
      benchmark (GAIA L1, SWE-bench Lite subset, WebArena-lite, tau-bench, or
      ARC-AGI), generated by `isaac eval`, with model + dataset + date in README.
- [ ] **Golden suite**: >= 30 representative real tasks (coding, file-org,
      research, design, ops) pass at an agreed bar with a named local model and
      a frontier fallback — transcripts stored.
- [ ] **Reliability**: zero non-terminating runs on the golden suite; budgets,
      no-progress detection, and tool-arg validation in place.
- [ ] **Security sign-off**: threat model written; `shell`/`fs_*` defaults
      scoped (no `~/.ssh`, `~/.aws`, browser profiles, `.env`); constitution
      red-team suite green; `pip-audit` clean or triaged.
- [ ] **Installable**: `pip install` works on Windows/Linux/macOS, py3.10-3.12;
      `isaac doctor` preflight passes; Docker/Xvfb are optional, not required.
- [ ] **Observability**: per-run traces persisted; latency + cost surfaced.
- [ ] **Honest docs**: capabilities labelled stable/beta/experimental; a
      `LIMITATIONS.md`; a model card; `SECURITY.md`.

## 2. Workstreams

Each workstream lists the **goal**, the **tasks**, and the **acceptance
criteria** (how we know it's done). They map to the problems flagged in the
1.0 review.

### WS1 — Evaluation & Benchmarking  *(fixes: "SOTA has no evidence")*
**Goal:** turn "SOTA" from an adjective into a measurement.
- Build `isaac eval`: load a task suite (JSONL of `{prompt, checker, files?}`),
  run the agent/orchestrator, score with programmatic checkers + an optional
  LLM judge, and write results to a SQLite results DB.
- Adopt 1-2 public benchmarks (cheapest-signal-first): ARC-AGI (we already have
  a solver), GAIA level 1, a SWE-bench Lite slice.
- Author an internal **golden suite** of 30-50 tasks spanning every specialist.
- Add a **nightly** eval CI job (separate from PR CI) that runs the golden
  suite against a pinned local model and publishes a scoreboard artifact.
- Surface results via `isaac eval --report` (reuse the MetaLearner store).
**Acceptance:** a one-command reproducible score; a cited number in the README.

### WS2 — Reliability & end-to-end validation  *(fixes: "no real runs", "robustness")*
**Goal:** the loop finishes, recovers, and never melts down.
- Real end-to-end runs (live model) for each specialist; save transcripts as
  regression fixtures.
- **Loop hardening** in `AgentLoop`/`Orchestrator`: max-iteration + no-progress
  detection (repeated identical tool calls -> stop), per-tool timeouts, total
  wall-clock and token budgets, graceful "I could not finish because...".
- **Tool-arg validation**: validate each tool call against its JSON-Schema
  before executing; return a correction message instead of crashing.
- Retry/backoff for transient LLM/tool errors; per-tool circuit breaker.
- A scripted **fake-LLM failure harness** that drives the orchestrator's
  parallel/dependency paths with some subtasks failing -> assert graceful synthesis.
- Persist run traces from the existing `on_event` stream; add `isaac trace <id>`.
**Acceptance:** 0 non-terminating runs on the golden suite; injected-failure
tests pass; every run yields a stored trace.

### WS3 — Model strategy & capability ceiling  *(fixes: "7B caps capability")*
**Goal:** be genuinely capable, not just architecturally capable.
- Make `MultimodalRouter` the single routing path; verify fast/default/strong
  map to good local models; document a recommended local stack
  (e.g. `qwen2.5-coder:14b/32b`, a strong tool-calling model) as presets.
- First-class, opt-in **frontier fallback** (Claude/GPT) for the `strong` tier
  when keys are present, with explicit cost controls.
- **Reliable tool-calling for small models**: JSON/grammar-constrained tool-call
  mode (llama.cpp grammars / Ollama `format=json`), few-shot tool exemplars, and
  a reflexion retry when a call is malformed.
- **Test-time compute** for hard steps: self-consistency / parallel sampling,
  reusing the ARC solver's "exit early on success" pattern.
- Benchmark local-vs-frontier on the golden suite and publish the gap honestly.
**Acceptance:** documented good/better/best presets; small-model malformed
tool-call rate below an agreed threshold after JSON-mode + retry.

### WS4 — Security & safety hardening  *(fixes: "host-reach liability")*
**Goal:** earn the right to run `shell` and touch real files.
- `docs/THREAT_MODEL.md`: assets, adversaries (prompt injection via web/files),
  trust boundaries.
- **Tighten defaults**: `allowed_paths` -> a dedicated workspace, NOT the whole
  home; explicit opt-in per directory; hard-deny sensitive paths (`~/.ssh`,
  `~/.aws`, browser profiles, `.env`, keys) in `fs_*` and the constitution.
- **Constitution red-team**: adversarial suite (base64/obfuscation, env-var
  expansion, unicode homoglyphs, chained commands) — confirm criticals stay
  blocked; add rules for every gap found.
- **Shell hardening**: keep `unrestricted` OFF by default; even on, run the
  constitution + log every command; run host commands with a scrubbed env.
- **Secrets hygiene**: redact secrets from tool outputs and traces.
- **Approval UX**: real human-in-the-loop approval for risk-4/5 in REPL/TUI,
  not just all-or-nothing `auto_approve`.
- **Prompt-injection defense**: provenance-tag tool outputs ("untrusted web
  content") so the model treats them with suspicion; route through the Guard node.
- `SECURITY.md` + responsible disclosure; `pip-audit` in CI.
**Acceptance:** red-team suite green; a default install cannot read `~/.ssh`;
`pip-audit` clean or triaged; security review signed off.

### WS5 — Packaging, install & developer experience  *(fixes: "setup friction")*
**Goal:** a stranger can run it in under 10 minutes.
- Publish to PyPI (`pip install isaac-agent`); verify wheels on Win/Linux/macOS,
  py3.10-3.12; rationalize dependency-version ranges.
- `isaac doctor`: preflight checking Python, Ollama reachability + model
  presence, optional Docker, optional deps — with actionable fixes.
- Make Docker/Xvfb **optional**: the `code` tool falls back to a restricted
  local subprocess sandbox when Docker is absent (clearly labelled less-isolated);
  computer-use gated behind an extra.
- Rationalize optional-dependency groups; ensure the CI's `pip install -e .[dev]`
  collects/runs **all** tests with optional deps **absent** (skip, never error).
- One-command bootstrap + a "batteries-included" docker-compose path.
- **Pin lint tools** (`ruff==<version>`) to stop CI formatting drift (the issue
  that broke CI at 0.4.0).
**Acceptance:** clean-machine install succeeds; `isaac doctor` green; `[dev]`-only
CI runs 100% of tests with no collection errors.

### WS6 — Memory & self-improvement maturation  *(raises capability using what exists)*
**Goal:** make "self-learning" real and measurable.
- Close the loop: the `Orchestrator` already records outcomes to the
  `MetaLearner` — now **use** it (via `strategy_ranker`) to bias specialist
  selection, not just LLM choice.
- Validate consolidation (episodic->semantic) doesn't forget/drift; add metrics.
- Skill-library quality gates: only promote skills that pass a verification run;
  deprecate by telemetry (scaffolding exists — validate end-to-end).
- Prove A/B prompt evolution improves the golden-suite score (ablation).
**Acceptance:** an ablation showing MetaLearner-guided selection >= baseline.

### WS7 — Product surface & UX
**Goal:** pleasant to use daily.
- Stream orchestrator/specialist events in the REPL/TUI; cancel/interrupt;
  resumable runs.
- Persona UX polish (preview/switch; per-persona tool + risk policy).
- Better final-answer formatting; researcher citations; an artifacts index for
  designer/file-org outputs.
- `isaac history` + `isaac replay <run_id>`.
**Acceptance:** a usability pass + demo recordings in the README.

### WS8 — Positioning, docs & governance  *(fixes: "honest framing")*
**Goal:** claims match reality.
- README rewrite: "local-first autonomous agent **framework**"; a capabilities
  table marked stable / beta / experimental; benchmark numbers with caveats.
- Model card + eval card; `LIMITATIONS.md` (honest failure modes).
- `CONTRIBUTING`, issue templates, a public roadmap board.
- AGPL compliance notes for downstream users.
**Acceptance:** no unsubstantiated "SOTA" anywhere without a cited number; a
reader can tell stable vs experimental at a glance.

## 3. Milestone plan (phased — ship increments, not a big bang)

| Release | Theme | Workstreams | Exit criteria |
|---|---|---|---|
| **0.5.0** | Reliable core | WS2, WS5, WS4 (part 1: path scoping + secrets) | Golden suite runs end-to-end with no infinite loops; clean-machine install; `[dev]`-only CI runs all tests |
| **0.6.0** | Measured | WS1 (harness + first benchmark number), WS3 (presets + JSON tool-mode) | A real benchmark number in the README; small-model tool-calls reliable |
| **0.7.0** | Hardened | WS4 (full), WS6 | Security sign-off; positive self-improvement ablation |
| **0.8.0** | Polished | WS7, WS8 | < 10-min onboarding; honest, labelled README |
| **1.0.0-rc -> 1.0.0** | Freeze & prove | full benchmark battery, external review | API freeze; cited numbers + security statement; all section-1 boxes checked |

---

## 4. The "SOTA" claim gate (explicit rule)

Do **not** use the word "SOTA" in any public artifact until **all** hold:
1. A public-benchmark number is reproduced by `isaac eval`.
2. It is competitive against a **named** comparison system.
3. The number, model, dataset, and date are in the README.

Until then, the honest description is **"a competitive local-first autonomous
agent framework."**

---

## 5. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Local model too weak for hard tasks | Frontier fallback + JSON tool-mode + test-time compute; set expectations in docs |
| Security incident from host tools | Conservative defaults, red-team suite, approval UX, scrubbed env |
| Scope creep / never-ship | Strict per-milestone exit criteria; ship increments |
| CI / tool-version drift | Pin lint tools; nightly eval separate from PR CI |
| Optional-dep import errors on minimal installs | Guard every optional import; tests skip (not error) when absent |

evidence — the foundation everything else builds on.
